## 逐条核验

先根据 doc_id 在 sample_documents.json 找全文。text 是本次使用的任务一 clean_content。
根据 mention_id 和 [start,end) 查看这一处代词，核对原句。所有下标是 Unicode 字符零基、左闭右开，不能按字节或用改写后的文本定位原始区间。

独立阅读全文及前后句，判断有没有明确先行词，再对照参考。linked 应给出原文中的先行词及其字符区间。相同名称重复出现时，还需选定对应的那次出现。unresolved 表示没有明确先行词，nonreferential 表示纯词形引用，ambiguous 表示无法唯一确定。不要把所有未链接都判为正确。

特别核对以下例子。
- C17 / YHY_T05:280:281 的“这”应指向佛香阁 [276,279)，当前系统漏消解。
- C22 / YHY_T05:1133:1135 的“这些”应指向无轨电车 [1073,1077)，当前系统漏消解。
- C20 与 C21 同句两个“她”的位置不同，应分别检查。
- C09 与 C24 为不确定案例，不纳入本次 25 例评价。
- 未到访的景点也可作先行词，共指链接不表示实际到访。

## 程序校验

在本 result 目录打开终端执行以下命令，仅使用 Python 标准库。
python verify_reviewed_result.py

它检查全量实体映射、27 例参考区间与指标计数，验证原始结果的哈希。该检查不替代语义判断。

如需在原任务四 V2 项目中使用本目录，先备份该项目原 result，再将本目录放入项目根目录。修改标注时，建议将“核验标注.csv”另存为“我的核验.csv”，在项目根目录执行。
python coref.py evaluate --annotations ./result/我的核验.csv --output ./result

评价程序按 mention_id 对齐，要求至少 5 个有效案例和标注人。ambiguous 排除，linked 按先行词起止位置严格匹配，无链接参考与无链接预测对应时算正确保留。指标口径如下。
- 链接准确率 = 正确链接 / 系统给出链接数，本次 19/19。
- 链接召回率 = 正确链接 / 参考 linked 数，本次 19/21。
- 覆盖率 = 系统给出链接数 / 可判定案例数，本次 19/25。
- 总体准确率 = (正确链接 + 正确保留) / 可判定案例数，本次 23/25。

修改人工标注后重新评价，会更新 coref_metrics.json。核验对照页面及 reviewed JSON 是本次标注的快照，若标注改变需同步更新对应快照，避免混用不同版本。新增规则修正两处漏消解时，应在新目录重跑消解与评价。
