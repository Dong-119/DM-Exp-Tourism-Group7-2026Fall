## 运行方式

进入 task4_coref_v2 目录执行，Python 3.9 或以上，Jieba 固定为 0.42.1。

~~~powershell
conda activate datamining
python -m pip install -r requirements.txt
python coref.py run
python verify_outputs.py
~~~

默认读取 data/clean_documents.jsonl 与 data/entities_v2.json，结果写入 result。重新运行会更新预测、对照和核验页面。已填写的人工标注模板会保留；已填模板与新样本不一致时，请使用新输出目录。

可以分阶段运行。

~~~powershell
python coref.py detect --output ./my_result
python coref.py resolve --output ./my_result
~~~

自选 3—5 篇游记时，两阶段使用相同的 --docs。也可一键运行。

~~~powershell
python coref.py run --docs GG_S04 YHY_T05 TT_T04 --window 250 --sentence-window 3 --output ./my_result
~~~

使用其他实体文件时，通过 --entities 指定。输入变化后需重新检测，已有提及会按正文哈希检查是否与输入一致。任务二 POI 切片也逐条核对。

## 4.1 代词检测与样本构建

分句使用中文句末标点、问叹号、分号和换行的正则。Jieba 在每句中做分词并提供词边界，HMM=False。它的作用是辅助确定词边界。

检测范围包括它、它们、他、她、他们、她们、这、那、这里、那里、这儿、那儿、此处、此地、原地、其、前者、后者、彼此及这个、这些、这种等指示表达。第一、第二人称没有纳入默认篇内名词消解范围。长词先匹配，单字需符合词边界；“这是”“这很”等结构补充独立“这”，并避免从“其他”内部拆出“他”。

每一次提及以 doc_id:start:end 标识。保存全文起止位置、句内位置、同句同形词的序号、原句与句子编号、前后上下文、来源信息和正文 SHA-256。位置针对原始 clean_content，Unicode 字符从 0 计数，结束位置不包含。相同代词在同一句出现两次会生成两条不同记录，例如 YHY_T05 的 [685,687) 和 [697,699) 两处“它们”。

sentences.json 保存分句结果。mentions.json 中的 tokens 保留该句的 Jieba 分词及位置，便于检查检测规则。sample_documents.json 保存所选全文和来源。

## 4.2 标注格式

人工标注模板.csv 提供所有待消解行，预测另存在结果文件中。标注列包括 status、antecedent_text、antecedent_start、antecedent_end、antecedent_type、annotator、notes。

status 可填写 linked、unresolved、nonreferential 或 ambiguous。linked 填写具体先行词原文、整篇字符区间和类型；其他状态留空先行词字段。先行词类型为 POI、PERSON、GROUP、ANIMAL、VEHICLE、OBJECT 或 EVENT。无法确定所指时可标 ambiguous，有充分依据认定篇内不存在明确先行词时标 unresolved，纯引用或非篇内名词指代标 nonreferential。

本次交付把该部分留给后续核验，未生成已完成的人工参考答案。

## 4.3 候选生成与选择逻辑

候选来自任务二 POI 和显式名词短语。补充售票员、朋友、老师、孩子等人物，大熊猫等动物，无轨电车等车辆，以及建筑物、照片等物体。候选词表在 coref.py 顶部可查。人群识别覆盖“几个朋友”“一群孩子”等结构，复数人称代词本身不会进入先行词候选。

默认同时满足 250 字距离和当前句之前最多 3 句的限制，只取代词之前的候选。每条预测保存通过窗口筛选的完整候选列表。

| 情形 | 规则 |
|---|---|
| 那里、这里、原地等地点表达 | 优先匹配 POI 候选 |
| 他、她 | 匹配显式人物，连续同形人物代词在当前分句无新人物时沿用近邻链接 |
| 他们、她们 | 只考虑明确的人群候选，无人群时保留 |
| 它 | 根据最近的景点、物体、车辆或动物名词选择 |
| 它们 | 仅在有动物名词或可靠近邻动物指代链时链接，其他复数景物保留 |
| 前者、后者 | 查找附近同一句中有并列或先后线索的不同景点，分别取前项、后项 |
| 当前句“名词是……，它……” | 用句首说明主语缓解最近宾语误选 |
| 引号内的代词本身 | 保留，标记为 nonreferential |
| 讨论“先行词、替换、强行对应”的分句 | 保留，标记为 ambiguous |
| 这、这些、这个、其所属对象不清等 | 保留供核验，记录原因 |
| 没有合适类型候选 | 保留，标记为 unresolved |

baseline_antecedent 保存窗口内不加类型判断的最近候选，便于对照。该基线共用本版的候选集合；它的定义与旧包候选范围不同。

## 4.4 输出和核验入口

| 文件 | 内容 |
|---|---|
| 核验结果.html | 当前代词高亮、位置、候选、预测依据及全文对照，离线打开 |
| 逐条核验.csv | 82 行预测，便于筛选已链接和保留项 |
| mentions.json | 全部检测提及及来源、位置、句子 |
| coref_predictions.json | 检测字段、窗口候选、基线及本版预测、状态和规则 |
| antecedent_candidates.json | 每篇文档的完整候选池 |
| resolved_texts.json | 原文、消解后全文、每次替换的两版字符区间 |
| coref_relations.json | 代词提及 COREFERS_TO 具体候选的结构化关系 |
| run_summary.json | 参数、输入哈希、状态及分文档计数 |
| 人工标注模板.csv | 留空判断字段供后续填写 |

例如 GG_S04 的“我先带孩子到太和殿。它是……”中，“它”链接到“太和殿”。“前者”与“后者”分别链接“太和殿”“中和殿”。YHY_T05 的“它基本上由两节车厢组成”链接“无轨电车”，“她大声地说”链接“一个售票员”。正文中的“不能把它强行对应到某一个景点”保留原词。

resolved_texts.json 的 edits 保存 original_start/end 和 resolved_start/end。修改前后的字符位置不同，查看改写文本时使用 resolved_start/end，回查原文时使用 original_start/end。关系表示文本共指，是否到访仍需结合原句，不能把“没有去”的地点当作已到访。

## 4.5 后续评估入口

填写至少 5 个明确结论的案例后，另存人工标注.csv，再执行。

~~~powershell
python coref.py evaluate --annotations ./result/人工标注.csv
~~~

明确 linked 的先行词按原文位置严格匹配。unresolved 和 nonreferential 以无链接为参考。ambiguous 单列，不纳入正确率分母。标注人必填，空行跳过。linked 的先行词必须在代词前面且切片还原原词。

链接准确率＝正确链接／系统给出链接数。
链接召回率＝正确链接／参考 linked 数。
覆盖率＝系统给出链接数／计入评价的样本数。
总体准确率＝（正确链接＋正确保留）／计入评价的样本数。
分母为零时对应比率保存 null。

本包没有生成 coref_metrics.json。人工判断完成后再运行评价入口。

## 验证和仍需核验的问题

已检查 82 条提及的原词、原句、句内位置、先行词方向及替换前后映射，均一致。相同输入连续两次运行，提及、预测、改写和关系 JSON 字节一致。还检查了同句重复代词、词内误切、成对指代、元语言分句和未来候选排除。

当前仍使用有限词表和局部规则。新的人物名、复数景物集合及跨段事件指代可能无法链接。嵌套引语、比较句和多个竞争人物也可能出错。保留原词既可能是合理的不确定判断，也可能是漏消解，需要逐句核验。41 处链接是系统输出数量。
