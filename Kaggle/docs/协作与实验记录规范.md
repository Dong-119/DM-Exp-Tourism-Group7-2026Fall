# 竞赛协作与迭代规范

**持续优化、显著提升才晋升版本及空闲服务器使用细则**见同目录的 [持续迭代与版本晋升规范.md](持续迭代与版本晋升规范.md)，该文件优先作为实验决策依据。

## 固定规则

1. 官方原始文件只存本地 data/raw/，不修改；GroupKFold 五折，以 prompt_id 分组，确保训练/验证 Prompt 互斥。
2. 每轮先提出一个有依据的改动、固定验证方案进行对比，记录 Balanced Accuracy 及各类召回率，再决定是否提交 Kaggle。
3. 只由一位组员负责正式提交。每次提交注明对应 Git commit 或本地版本、Notebook 版本、提交时间、公榜成绩。
4. 组员在独立 Git 分支开发，提交 Pull Request，经检查后合并；不得同时直接改 main 的相同文件。
5. Git 只共享可复现代码、配置、非敏感汇总表和主要结论；原始数据、逐条 OOF、模型权重、凭据及未经筛选的输出不上传。

## 每一轮的最小记录

- 版本、日期、负责人、目的 / 假设
- 数据版本（train.csv SHA256）、切分方式、随机种子（若适用）
- 模型、特征、关键参数、运行命令 / 代码版本
- 各折 Balanced Accuracy、整体 OOF Balanced Accuracy、每类召回率和混淆情况
- 与上一轮对比、结论、下一步
- 正式提交时：Submission ID、Notebook、Public LB、截图路径；未提交标注“未提交”

## 截图与课程交付

- Team Page：组队信息，尽早保存一次
- Submission History：至少五次有效提交及公榜成绩变化（每次保留提交 ID 与版本记录，必要时逐次截图）
- Private Leaderboard：竞赛结束后最终成绩截图
- 课程 Word 报告、Excel 成绩汇总使用原有学校模板；注意报告截止早于私榜公布，询问助教能否补充结果

截图建议保存在本地 outputs/evidence/，需要共享时人工检查是否涉及账号隐私后再上传。
